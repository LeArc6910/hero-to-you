# 웹 플레이 시험 (클라우드가 대신 해 보기)

사람이 휴대폰과 PC로 해 보며 보던 확인을 클라우드 세션이 먼저 한다(사용자 요청, 2026-11-09: "클라우드에서 테스트까지 너가 자동으로"). 클라우드 컨테이너의 헤드리스 Chromium으로 GitHub Pages의 웹 데모를 띄우고, 실제 마우스 클릭과 터치 탭으로 게임의 단추를 누르고, 화면을 찍어 클라우드가 본다. Unity가 없어도 된다. WebGL은 SwiftShader(소프트웨어)로 그린다. 사용자의 다른 프로젝트(pray-to)의 방식을 이 게임에 맞게 옮겼다.

## 돌리는 법

```
# 배포된 웹 데모로 지금 바로
node DevTools/WebPlaytest/playtest.js

# 방금 푸시한 커밋이 배포될 때까지(빌드는 15~20분) 기다렸다가
node DevTools/WebPlaytest/playtest.js --wait

# 화면 하나만: pc(1280×720), pc-small(800×600), phone(390×844 세로), phone-wide(844×390 가로)
node DevTools/WebPlaytest/playtest.js --profiles phone

# 로컬에서 띄운 빌드로
node DevTools/WebPlaytest/playtest.js --url http://localhost:8000/
```

결과는 `DevTools/WebPlaytest/out/`에 사진(`<화면>-<장면>.png`)과 `report.md`(확인마다 통과·실패, 브라우저가 본 에러)로 남는다(커밋하지 않는다). 클라우드는 사진을 열어 보고, 사람에게는 사진으로 알 수 없는 것만 묻는다.

## 무엇을 해 보는지

화면마다(PC는 마우스, 휴대폰은 탭):

1. 타이틀: 한글 제목, 터치 인식, [연습 판]·[저장 슬롯]이 있는지, 단추가 서로 겹치지 않는지, [저장 슬롯] 화면(빈 슬롯 셋), [설정](글자 크기를 바꾸면 바뀌는지, 언어를 영어로 바꾸면 메뉴가 영어인지)
2. [새 모험] → 파티 카드 셋(기사·사냥꾼·성직자) → 조합 줄이 보이는지, 아래 단추가 겹치지 않는지 → [모험 시작] → 프롤로그(글이 한 글자씩 나오는지, 누르면 다 나오는지, 장면 그림 사진)
3. 지도: 기기에 저장됐는지, 안개(모르는 칸이 있는지), 처음 보는 화면의 도움말 카드와 [알겠다], [이동 굴리기] → 칸 하나 누르기 → 패널 → [이동], [장비·소모품] 창
4. 봇이 걸어 전투가 날 때까지(`autoplay`) → 합류 고르기 → [싸운다] → 물약·[도망] 단추가 있는지, 기술 단추를 길게 누르기(휴대폰)·가리키기(PC)로 설명이 나오는지(누른 것으로 치지 않는지), 진짜 명령 하나(대상, [굴리기], 주사위 연출 사진) → 나머지는 봇
5. 레벨업 강화 고르기(나올 때까지 봇)
6. 페이지를 새로 고친 뒤 [이어하기]: 같은 명령 수에서 이어지는지
7. PC만: 줄(기사 앞줄·사냥꾼 뒷줄), 모닥불 대화 카드, 던전 방 사이 화면, 3장 지도 사진, 마을(상점 사진, [소문을 듣는다]로 안개가 걷히는지, 영웅에게 물약 사 주기), 캠페인 끝까지(중간 보스·보스 사진, 2장 이야기와 지도 사진, 끝 화면, 저장이 지워졌는지, 일지 페이지를 받았는지), 끝 화면의 [기록 복사]와 복사되는 기록(`share`), 타이틀의 [일지] 화면, 다다른 장(`reached 3`)으로 [시작: N장]·[길이] 단추를 눌러 2장 한 장짜리 판이 레벨 5로 시작하는지와 끝난 판이 비운 슬롯을 다시 쓰는지, [연습 판](쉬움·1장만·슬롯 0)

## 게임 쪽 원격 조종 (`Client/Playtest.cs`)

페이지가 `unityInstance.SendMessage("Game", "Playtest", "<명령; 명령>")`을 부르면 듣는다. 명령마다 콘솔에 `[playtest] <명령> <답>`으로 답한다.

| 명령 | 하는 일 |
|---|---|
| `probe on\|off` | 단추와 글을 기록한다(`buttons`, `texts`에 필요) |
| `buttons` | 마지막 화면의 단추마다 글자, 줄(`row`: 직업·기술·대상·선택지·칸·합류·강화·상점 같은 묶음), 화면 위치(점), 눌리는지, 보이는지(JSON) |
| `texts` | 마지막 화면에 쓴 글 |
| `report` | 상태 한 줄(JSON): 화면, 일지 페이지·가져갈 장, 날·시간·균열, 금화·희망, 장·명성·명성 이름, 모르는 칸·본 칸 수, 피하기·겁주기 가능, 찾은 메모 수, 열린 도움말 카드(`tip`)와 떠 있는 설명(`tooltip`), 음악 음량, 지도 차례·이동력·갈 수 있는 칸 수, 레벨업 대기, 저장 여부, 영웅들(위치·무기·소모품), 전투, 사건 |
| `start <직업,직업,직업> [시드]`, `seed <n>`, `title` | 바로 모험 시작, 다음 모험의 시드, 타이틀로 |
| `continue`, `roll`, `move <열> <줄>`, `stay`, `camp`, `join`, `upgrade <n>` | 모험 명령(join은 갈 수 있는 영웅 모두) |
| `goto town\|quest\|boss\|shrine\|<열> <줄>` | 지금 영웅을 그곳 옆 빈 칸으로 옮긴다 |
| `auto`, `autobattle`, `skip` | 봇이 지금 영웅의 명령 하나, 전투 끝까지, 남은 연출을 바로 |
| `autoplay <n>` | 모험 봇이 n걸음(지도·사건·마을·전투 모두) |
| `choose <선택지> <영웅> [결의]`, `autochoose` | 사건 선택지 |
| `speed <배>` | 연출 속도(0은 바로) |
| `touch on\|off\|auto`, `gear on\|off`, `sound on\|off` | 터치 배치, 장비 창, 소리 |
| `hurt <영웅> <양>`, `resolve <영웅> <양>`, `give <영웅> <아이템> [개수]` | 상황 만들기 |
| `avoid`, `scare`, `reroll`, `rumor`, `donate`, `use <영웅> <아이템>` | 새 모험 명령 |
| `endchapter` | 장의 보스를 이긴 것으로 치고 결말 이야기로(다음 장을 보러) |
| `tips off\|reset`, `tip <id>` | 도움말 카드를 모두 본 것으로 / 다시 나오게, 카드 하나 열기. `probe on`은 카드를 모두 본 것으로 한다 |
| `pages <n>`, `screen journal\|settings\|party\|title` | 일지 페이지 더하기, 화면 바꾸기 |
| `row <영웅> front\|back`, `delve`, `leavedungeon`, `contract`, `wound <영웅>` | 줄, 던전, 의뢰, 상처 |
| `chapter <n>` | 앞 장의 보스를 이긴 것으로 치고 n장 시작으로 |
| `forge <영웅> weapon\|armor\|trinket`, `recruit <직업>`, `gold <n>` | 대장간, 새 동료, 금화 |
| `hardcore on\|off`, `autobutton on\|off`, `history on\|off`, `retry` | 다음 판의 하드코어, 자동 전투, 지난 일 창, 이 장 처음부터 |
| `bugreport on\|off\|text` | 버그 제보 창, 또는 제보 글 자체를 답한다 |
| `talk` | 마지막 동료 대화를 카드로 다시 보인다(`autoplay`는 봇이 들은 대화의 카드를 띄우지 않는다) |
| `difficulty easy\|normal`, `language ko\|en`, `textsize <%>` | 다음 모험의 난이도, 언어(시트를 그 언어로 다시 읽는다), 글자 크기 |
| `slot <n>`, `screen slots`, `practice` | 새로 시작하고 이어 할 저장 슬롯(0은 연습 판), 슬롯 화면, 연습 판 시작 |
| `reached <n>`, `range <n> [one]` | 일지가 다다른 장, 파티 화면의 시작 장(1부터)과 한 장짜리 판 |
| `share` | 끝 화면의 [기록 복사]가 복사하는 글(줄을 ` \| `로 이어서) |

`report`에는 `slot`, `reached`, `startChapter`, `oneChapter`와, 모험 중이면 `firstChapter`, `lastChapter`, `combos`(그 파티의 조합 id)도 있다.

단추는 모두 `Ui.Button`이나 `Ui.Hit`를 거친다(`Ui.cs`). 시험이 `probe on`을 켜 두면 그린 단추를 기억하고, 시험 도구(`lib.js`의 `press`)는 그 자리를 진짜 클릭이나 탭으로 누른다. 새 단추도 이 둘로 만든다.

## 버그 제보를 받으면

사람이 설정의 [버그 제보]로 보낸 글(첫 줄이 `# hero-to-you bug report`)을 파일로 저장해 `dotnet run --project DevTools/CoreSandbox -- --replay report.txt`로 돌린다. 같은 상태(장, 날, 영웅, 전투의 마지막 일)가 나온다. 고친 뒤에는 그 저장본으로 시험을 하나 더한다.

## 사진으로 알 수 없는 것

손맛(주사위가 굴러가는 시간, 숫자가 뜨는 리듬, 공격할 때의 돌진), 소리와 음악(헤드리스 브라우저는 소리를 듣지 못한다. 파형 검사는 `DevTools/SoundPreview`), 길게 누르기의 감(0.45초), 실제 휴대폰의 손가락 감각과 성능, 이야기를 읽는 맛, 오래 해 보는 재미. 이것만 사람에게 묻는다.
