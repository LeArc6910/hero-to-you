# 웹 데모

작업 중인 최신 상태를 브라우저(휴대폰 포함)에서 바로 해 볼 수 있게 하는 빌드와 배포다. 주소는 https://learc6910.github.io/hero-to-you/ 이다(사람 설정이 끝나고 첫 배포 뒤). 사람이 처음 한 번 하는 설정(시크릿, Pages, 배포 브랜치)은 `Docs/WebDemoSetup.md`에 단계별로 있다.

## 흐름

1. `main`이나 `claude/…` 브랜치에 푸시하면 `.github/workflows/web-demo.yml`이 돈다. 문서(`*.md`, `Docs/`)와 `DevTools/`만 바뀐 푸시는 건너뛴다. Actions 탭에서 손으로 돌릴 수도 있다(Run workflow)
2. 시크릿 `UNITY_EMAIL`, `UNITY_PASSWORD`가 없으면 빌드를 건너뛰고 안내만 남긴다(실패로 표시하지 않는다)
3. GameCI의 Unity 이미지(`unityci/editor:ubuntu-<ProjectVersion의 버전>-webgl-3`) 안에서 `.github/scripts/build-web.sh`가 돈다
   - **라이선스**: 에디터에 들어 있는 Licensing Client로 Unity Personal을 활성화하고(`--activate-ulf --include-personal`, 시리얼 없음) 빌드가 어떻게 끝나든 돌려준다. 계정은 소셜 로그인이나 2단계 인증 없이 이메일·비밀번호로 로그인할 수 있어야 한다. 사용자의 다른 프로젝트(pray-to)에서 2026-10-28에 맞춘 방식을 그대로 가져왔다
   - **빌드**: `Game.Client.Editor.WebBuild.RunBatch`. 먼저 `Game > Set Up Project`(`ProjectSetup`)를 해서 설정과 `Main` 씬을 코드로 만들고, 커밋 해시를 `Resources/BuildInfo.txt`에 써서(타이틀 오른쪽 아래에 보인다) WebGL로 `build/web`에 빌드한다. 저장소에는 `ProjectSettings/ProjectVersion.txt`와 `Packages/manifest.json`, 코드와 데이터만 있어도 빌드가 된다(에디터에서 손으로 만든 것이 없다)
4. `version.txt`(커밋)를 넣어 GitHub Pages에 올린다. 클라우드의 플레이 시험이 이것을 보고 배포를 기다린다(`Docs/Playtest.md`)

## 휴대폰에서 해 보기

- 위 주소를 휴대폰 브라우저로 연다. **가로로 들고** 하는 쪽이 편하다(세로도 된다)
- 모든 조작은 누르기다
  - **지도**: [이동 굴리기] → 금색 테두리 칸 하나를 누르면 오른쪽(세로면 아래) 패널에 그 칸의 내용과 비용 → [이동]. 굴리기 전에 [야영], 굴린 뒤 [여기 머물기](도박사는 [다시 굴리기]). 지도가 화면보다 크면 끌어서 옮긴다. 어두운 칸은 안개. [장비·소모품]으로 장비를 바꾸고 물약을 쓴다
  - **전투**: 기술 단추 → 적이나 아군을 눌러 대상 → [−]/[+]로 결의 → [굴리기]. 소모품 단추와 [도망]도 같은 곳에 있다
  - **합류**: 함께 싸울 영웅을 켜고 끈 뒤 [싸운다]. 들판의 무리는 [피해 간다](광전사는 [겁줘 쫓는다])
  - **설명**: 단추나 위쪽 영웅 칸을 **길게 누르면**(PC는 마우스를 올리면) 설명이 뜬다. 처음 보는 화면에는 도움말 카드가 한 번 나온다
  - **레벨업**: 강화 카드 둘 가운데 하나를 누른다
- 확률 막대: 성공 수(0개~전부)마다 나올 확률과 그때의 피해·회복. 금색이 완벽, 회색이 0개
- 주사위 칸의 숫자가 확률보다 작으면 성공(초록), 금색 ★은 확정 성공(결의·표식·협공·축복·공명·기습)
- 점성술사가 있으면 전투 패널에 "다음 주사위: 12 · 87 · 45"가 보인다. 다음에 굴릴 주사위의 수다
- 명령마다 기기에 저장된다. 다시 열면 타이틀의 [이어하기](`Docs/Saving.md`)
- 타이틀의 [일지](판이 끝날 때 받은 페이지로 장을 펼치고 다음 판에 가져갈 것을 고른다)와 [설정](글자 크기, 진동, 효과음, 음악, 전투 연출 속도, 도움말 다시 보기, 언어)
- 설정에는 [색약 표시](성공·실패를 파랑·주황과 ✓·×로), [움직임](흔들림·돌진·눈 내림 줄이기), [버그 제보](지금 판의 저장을 복사하거나 파일로 받아 대화창에 보내면 클라우드가 그대로 재현한다)도 있다
- 전투의 [자동]은 봇에게 명령을 맡긴다. 지도의 [지난 일 보기]는 지금까지의 일을 보여 준다. 장에서 지면 끝 화면의 [이 장 처음부터]로 다시 한다
- 마을의 대장간에서 장비를 벼린다(+3까지)
- 파티를 고를 때 [난이도: 보통/쉬움]과 [하드코어], 한 번 가 본 장이 있으면 [시작: N장]과 [길이: 끝까지/한 장](짧은 판, `Docs/Map.md`). 고른 직업의 조합이 금색 줄로 나온다. 장비 창에서 영웅마다 [앞줄]/[뒷줄]을 바꾼다
- 타이틀의 [연습 판]: 처음 하는 사람을 위한 1장짜리 쉬운 판(정해진 파티와 지도, 도움말을 다시 보인다). 화면 아래 안내 줄이 다음에 할 일을 말하고, 눌러야 할 단추가 금색으로 깜빡인다(이야기 → 이동 굴리기 → 칸 고르기 → 이동 → 합류 → 기술 → 대상 → 굴리기, 사건·마을·레벨업도). [안내 끄기]로 끄고, 연습 판을 새로 시작하면 다시 켜진다(`GameRoot.Tutorial.cs`). [저장 슬롯]: 모험 셋을 따로 저장한다
- 끝 화면의 [기록 복사]: 파티·레벨·전적·결말을 몇 줄로 복사해 나눌 수 있다
- 마을의 [의뢰를 맡는다]: 지도에 깃발이 선 무리를 쫓아내고 돌아오면 보상. 지도의 동굴 칸은 던전(방마다 [더 들어간다]/[나간다])

## 키보드 (PC, 2026-11-10)

마우스 대신 키로도 된다. 단추 오른쪽 위에 작게 키 이름이 보인다(휴대폰에서는 숨긴다). `Ui.Button`·`Ui.Hit`의 `key`로 단다.

| 키 | 하는 일 |
|---|---|
| Space · Enter | 화면의 주된 단추: 계속, 이동 굴리기, 이동, 싸운다, 굴리기, 굴려 본다, 마을을 떠난다, 도움말 카드 닫기, 대화 계속 |
| 1~9 | 전투의 기술·소모품·도망, 사건의 선택지, 레벨업 강화 카드 |
| Tab | 전투에서 다음 대상 |
| − · + | 결의 줄이기·늘리기 |
| Esc | 창 닫기(장비, 지난 일, 버그 제보, 도움말), 뒤로(설정·일지·슬롯·파티), 다른 선택지, 던전에서 나가기 |
| C · S · G · H · R | 지도의 야영, 머물기, 장비·소모품, 지난 일, 다시 굴리기 |
| A | 전투의 자동 켜고 끄기, 레벨업의 남은 강화 알아서 고르기 |

## 작은 화면 (2026-11-10 배치 점검)

800×600 창, 휴대폰 세로(390×844)·가로(844×390), 글자 크기 130%에 들어가게 맞춘 것:

- 타이틀: 화면이 짧으면 단추 높이·간격·제목 크기를 줄이고, 그래도 넘치면 연습 판·저장 슬롯·일지·설정을 한 줄에 넷으로 놓는다. 협동은 단추 대신 작은 안내 줄
- 설정: 단추 줄이 넘치면 끌어서 넘긴다(가운데 영역만 스크롤, [뒤로]는 늘 아래)
- 파티 고르기: 아래쪽을 [뒤로]·[무작위]·[모험 시작] 한 줄, 그 위에 난이도·하드코어·시작 장·길이 한 줄(좁으면 두 줄), 그 위에 조합과 가져가는 장 줄로 나눴다. 예전에는 좁은 화면에서 난이도·하드코어 단추가 카드와 겹쳤다
- 전투: 기술이 많아(4개 + 기본 공격 + 소모품 + 도망) 두 열로는 [굴리기]가 밀려나는 낮은 패널이면 세 열로, 그래도 모자라면 단추 높이를 38점까지 줄인다
- 플레이 시험이 타이틀과 파티 화면에서 단추끼리 겹치지 않는지 본다(`playtest.js`의 `noOverlap`)

## 성능 (2026-11-10)

- 지도의 갈 수 있는 칸(`Adventure.Reachable`, 너비 우선 탐색)을 명령 수·지도 차례·이동력·위치가 바뀔 때만 다시 구한다(IMGUI는 한 프레임에 `OnGUI`를 여러 번 부른다)
- 음악을 처음 틀 때 한 번에 합성하면 웹(스레드 하나)에서 화면이 잠깐 멈췄다. 이제 곡을 화음의 부분마다 나눠 한 프레임에 4ms까지만 만들고, 그동안 앞 곡이 계속 나온다. 아무 곡도 기다리지 않을 때는 다음에 쓸 곡(이야기·숲·전투·마을·보스…)을 미리 조금씩 만든다(`Music.Prepare`)

## 웹 빌드 설정 (`Editor/ProjectSetup.cs`)

- gzip 압축 + decompression fallback(GitHub Pages가 `Content-Encoding`을 붙이지 않으므로 Unity 로더가 푼다), 데이터 캐싱, 시작 화면 끔, IL2CPP 크기 우선
- 페이지는 `Assets/WebGLTemplates/Fit`: PC에서도 창을 꽉 채운다. 마지막 입력이 손가락인지(`window.heroLastPointer`) 적어 둬 게임이 터치 배치를 고른다(`Client/WebBridge.cs`)
- 화면 밀도: 브라우저는 기기의 실제 픽셀로 그린다(휴대폰은 점 하나에 3픽셀쯤). `Ui`가 `devicePixelRatio`를 읽어 점 단위로 배치하고, 글자는 실제 픽셀 크기로 그려 흐리지 않다. 큰 모니터에서는 최대 2배까지 키운다
- 글꼴: 웹은 시스템 글꼴을 못 쓰므로 Noto Sans KR(SIL OFL 1.1, `Docs/Licenses/NotoSansKR-OFL.txt`) Medium의 부분집합(약 520 KB, KS X 1001 한글 2,350자 + 코드와 시트에 쓰인 모든 글자)을 넣었다. 새 글자를 쓰면 `DevTools/Fonts/make-korean-font.py`로 다시 만든다(원본은 스크립트 머리말의 주소)
- 렌더 파이프라인은 기본(Built-in). 입력은 IMGUI 이벤트만 쓴다(마우스 클릭과 탭이 같은 길로 들어온다)

## 아직 확인하지 못한 것

클라우드에서는 실제 기기로 돌려 볼 수 없다. 첫 배포 뒤 휴대폰에서 본다.

- 탭이 단추에 바로 반응하는지, 두 번 눌리지 않는지
- 글자 크기와 화면 배치(세로·가로)
- 주사위 연출의 속도와 손맛
