# hero-to-you 개발 가이드라인

가제는 **히어로 투 유(Hero to You)**. 탑뷰 2D, 턴제, 1~3인 협동 모험 RPG다. 이 문서가 기획과 기술의 기준이고, 방향이 바뀌면 코드보다 이 문서를 먼저 고친다. 정해진 것과 아직 열린 질문을 같이 적는다.

## 1. 어떤 게임인가

세 명의 모험가가 한 파티가 되어 지도 위를 턴마다 움직이고, 마을과 폐허와 숲에서 일어나는 사건을 함께 겪고, 턴제 전투로 몬스터를 물리치고, 챕터 끝의 보스를 쓰러뜨린다. 모든 행동은 주사위 판정으로 결과가 갈리지만, 결과를 정하는 것은 **플레이어의 선택과 캐릭터의 성장**이고 주사위는 그 위에 얹는 긴장감이다.

**느낌의 기준**(사용자 결정, 2026-11-09): For the King처럼 함께 지도를 돌며 확률 판정으로 싸우고 사건을 겪는 협동 모험. 하는 맛만 가져오고, 이름·그림·지도·사건 문장·수치는 가져오지 않는다. 규칙도 아래처럼 우리 식으로 바꾼다.

| | 이 게임 |
|---|---|
| 인원 | 1~3명. 영웅은 언제나 셋이고, 사람 수에 맞춰 나눠 조종한다(혼자면 셋 다) |
| 진행 | **턴제**(사용자 결정, 2026-11-09). 지도는 영웅마다 차례로 움직이고, 전투는 행동 순서표에 따라 한 명씩 행동한다 |
| 한 판 | 챕터 하나 45~70분. 휴대폰에서 끊어 해도 되게 칸마다 저장한다 |
| 화면 | 지도는 위에서 내려다보는 육각 칸, 전투는 영웅(왼쪽)과 적(오른쪽)이 마주 보는 2D 화면 |
| 출시 | PC(Steam)와 모바일(Android, iOS). 개발 중 확인은 웹 데모(브라우저, 휴대폰 포함) |

## 2. 디자인 기둥

| 기둥 | 뜻 | 지키는 장치 |
|---|---|---|
| **선택이 먼저, 주사위는 양념** | 같은 상황에서 더 나은 선택을 한 쪽이 거의 언제나 더 좋은 결과를 얻는다. 성장한 캐릭터가 운 때문에 초보처럼 무너지지 않는다 | 굴리기 전에 확률과 예상 결과를 보여 준다. 결의(확정 성공)로 운을 덜어 낸다. 실패는 끈기로 쌓여 결의가 된다. 결과는 성공/실패 둘이 아니라 단계로 나온다. 적의 다음 행동이 보인다 (`Dice.md`) |
| **직업마다 다른 게임** | 고른 직업에 따라 전투에서 하는 일도, 지도와 사건에서 할 수 있는 일도 달라진다. 수치만 다른 직업은 만들지 않는다 | 직업마다 고유 기믹(자원·규칙) 하나, 사건 전용 선택지, 지도 특기. 같은 상황이 직업 조합마다 다르게 풀린다 (`Classes.md`) |
| **셋이어야 완성되는 협동** | 각자 잘하는 일이 달라서 서로를 필요로 한다 | 협공(같은 적을 이어 치면 확정 성공), 수호·축복·표식처럼 남을 위한 기술, 함께 쓰는 희망, 가까이 있어야 전투에 합류 (`Combat.md`) |
| **함께 겪는 이야기** | 싸움 사이사이가 이야기다. 선택이 다음 사건과 결말을 바꾼다. **옛 영웅의 발자취를 따라 걷다 스스로 영웅이 되어 가는 서사시**(사용자 결정, 2026-11-09) | 챕터마다 본 줄거리, 영웅마다 개인 이야기, 직업에 따라 열리는 선택지, 기억되는 선택(플래그), 옛 영웅의 메모(발자취), 명성의 이름(길손 → 영웅), 장마다 셋으로 갈리는 결말. 이야기는 전부 데이터에 있어 통째로 바꿀 수 있다 (`Narrative.md`) |
| **짧게 끊어도 이어지는 모험** | 휴대폰에서 10분씩 해도, PC에서 한 시간을 해도 즐겁다 | 칸마다 자동 저장, 한 번의 전투는 3~5분, 한 손 세로·가로 모두 되는 UI |

## 3. 한 판의 흐름

```
파티 꾸리기(직업 셋) → 챕터 시작 이야기
  → 지도 턴: 영웅마다 이동 판정 → 칸에 들어가면 일이 생긴다
       전투 · 사건(선택지와 판정) · 마을(상점, 여관, 의뢰) · 성소 · 보물 · 던전(연속 전투)
  → 성장: 경험치로 레벨업(능력치 + 기술 강화 고르기), 장비, 소모품
  → 하루가 지나면 균열이 자란다(시간 압박) → 챕터 보스 → 결말 이야기, 일지 페이지
  → 다음 챕터 또는 새 파티(일지 페이지로 새 직업·사건·시작 장비가 열린다)
```

### 지도 턴 (M2, 자세한 건 `Map.md`)

- 육각 칸 지도. 지역(평원·숲·늪·산·폐허)마다 일어나는 일과 이동 비용이 다르다
- 영웅마다 차례로 움직인다. 차례가 오면 **이동 판정**(민첩 주사위)을 하고, 기본 이동력에 성공 수를 더한 만큼 칸을 간다. 기본 이동력은 언제나 보장한다
- 칸에 들어가면 그 칸의 일이 생긴다. 장소(마을, 성소, 본 줄거리, 보스)는 처음부터 보이고, 적 무리·사건·보물은 **안개** 속에 있어 가까이 가거나 소문을 들어야 보인다. 직업마다 지도 특기가 있다(사냥꾼은 숲을 쉽게 걷고 멀리 본다 등)
- 세 영웅이 모두 움직이면 시간이 한 단계(아침→낮→저녁→밤) 흐르고, 하루가 지나면 **균열**이 한 칸 자란다. 균열이 자라면 적이 세지고 지역이 오염된다. 본 줄거리의 일을 하면 균열이 줄어든다
- 흩어지면 더 많은 칸을 보지만, 전투는 가까이 있는 영웅만 합류한다(전투가 난 칸에서 2칸 안). 모일지 흩어질지가 지도의 큰 선택이다

### 전투 (M1)

`Combat.md`. 요약: 행동 순서표(속도에 따라 다음 8번의 차례가 보인다), 적은 다음에 할 일을 머리 위에 보여 준다. 내 차례에 기술과 대상을 고르고, 결의를 몇 개 쓸지 정하고, 확률과 예상 피해를 본 뒤 굴린다.

### 사건 (103개, 자세한 건 `Narrative.md`)

`Narrative.md`. 상황 글 → 선택지(직업·능력치 조건, 성공 확률 표시) → 판정할 영웅을 고른다 → 결과(보상, 피해, 플래그, 이어지는 사건).

## 4. 확률 원칙 (요약, 자세한 건 `Dice.md`)

1. **판정 = 주사위 여러 개.** 기술마다 주사위 수(1~7)와 쓰는 능력치가 정해져 있고, 주사위 하나가 성공할 확률은 그 능력치(%)다. 능력치가 오르면 바로 확률이 오른다
2. **결과는 단계로.** 성공 수에 비례해 효과가 커진다. 기술마다 바닥(성공 0개여도 나오는 비율)이 있다. 모두 성공하면 **완벽** 효과가 붙는다
3. **결의**: 영웅마다 2~5개. 하나를 쓰면 주사위 하나가 확정 성공이다. 쉬거나 전투에서 이기면 돌아온다
4. **끈기**: 내 판정에서 주사위가 실패할 때마다 1씩 쌓이고, 다 차면 결의 하나가 된다. 운이 나쁜 만큼 다음 선택의 폭이 넓어진다
5. **굴리기 전에 다 보여 준다.** 성공 수별 확률, 예상 피해, 완벽 확률. 숨긴 굴림은 없다
6. **무작위는 사건의 몫.** 무엇이 나타날지(어떤 사건, 어떤 적, 어떤 보물)는 무작위로 크게 흔들어도, 판정 하나하나는 성장을 따르도록 분산을 묶는다. 랜덤을 즐기고 싶은 사람에게는 도박사처럼 분산을 직접 키우는 선택지를 준다

## 5. 직업 원칙 (요약, 자세한 건 `Classes.md`)

출시 목표는 **12직업**, 그 뒤로 더한다. 직업마다 다음 넷이 다 달라야 한다.

- **고유 기믹**: 그 직업만의 자원이나 규칙(분노, 표식, 원소 순환, 판돈, 예지, 동료 늑대…)
- **전투 역할**: 막기, 근접, 원거리, 광역, 회복, 강화, 방해, 소환
- **사건과 지도의 특기**: 직업 전용 선택지(자물쇠 따기, 설득, 해독, 예견), 지도 능력(시야, 추적, 할인)
- **약점**: 혼자서는 메울 수 없는 빈틈이 있어야 협동이 산다

같은 셋이 두 번 나와도 지루하지 않게, 레벨업마다 기술 강화를 둘 중 하나 고른다. 직업 하나 안에서도 판마다 빌드가 갈린다.

## 6. 협동

- 영웅은 늘 셋. 사람마다 맡은 영웅이 있고, 그 영웅의 차례에는 그 사람만 고른다. 다른 사람은 **제안**(대상 가리키기, 짧은 신호)만 할 수 있다
- 사건 선택은 그 칸에 들어간 영웅의 주인이 한다. 판정할 영웅은 그 칸에 있는 영웅 가운데서 고른다
- 함께 쓰는 것: **희망**(쓰러진 영웅을 일으킨다, 파티에 하나), 지도 정보, 금화(M1은 파티 지갑 하나. 사람마다 지갑을 둘지는 M4 온라인 협동 때 다시 본다). 따로 쓰는 것: 가방(물약), 결의, 끈기
- 남을 위한 기술이 직업마다 하나 이상 있다(수호, 축복, 표식, 연주, 행운의 동전, 예지)
- 혼자 하는 사람도 셋을 다 조종한다. 같은 코드 경로를 써서 협동 버그가 혼자 할 때도 드러난다

## 7. 기술 원칙

### 7.1 Core가 게임이다

규칙과 상태는 전부 `Game.Core`(순수 C#, UnityEngine 참조 없음)에 둔다. 주사위, 전투, 사건, 지도, 성장, 저장 형식이 모두 여기다. Unity(`Game.Client`)는 화면, 입력, 소리, 네트워크 전송만 한다.

- 클라우드 세션이 Unity 없이 `dotnet`으로 만들고 테스트한다
- `DevTools/CoreSandbox`에서 봇 파티로 수천 판을 돌려 밸런스를 잰다(직업 조합별 승률, 판정 분포, 연속 불운 길이)
- 턴제라 프레임과 물리가 필요 없다. Core는 명령을 받아 상태를 바꾸고 **일어난 일(이벤트) 목록**을 돌려준다. 화면은 그 목록을 차례로 연출한다

### 7.2 명령과 결정적 난수

- 모든 입력은 명령(`BattleCommand`, 나중에 `MapCommand`, `EventChoice`)이다. 같은 시드와 같은 명령 순서면 어디서나 같은 결과가 나온다
- Core는 `System.Random` 대신 `GameRandom`(PCG32)을 쓴다. 시각도 Core 안에서 읽지 않는다
- 덕분에 버그와 밸런스 결과를 시드와 명령 기록으로 재현한다

### 7.3 멀티플레이: 호스트가 명령 순서를 정한다 (M4)

- 한 사람이 호스트다. 모든 사람의 명령은 호스트에게 가고, 호스트가 Core로 검증·적용한 뒤 **명령과 결과 해시**를 모두에게 보낸다. 다른 사람도 같은 Core로 같은 명령을 적용해 같은 상태가 된다(턴제 락스텝). 해시가 어긋나면 호스트의 상태 전체를 받는다
- 주고받는 양이 아주 적어 웹·모바일 회선에서도 가볍다
- 전송은 Unity Relay(방 코드)로 웹·PC·모바일이 한 방에서 논다. 자세한 건 M4에서 `Docs/Multiplayer.md`

### 7.4 데이터로 만든다

직업, 기술, 몬스터, 사건, 아이템은 CSV 시트(`Assets/_Project/Resources/Data`)다. Core가 직접 읽는다. 에디터에서 손으로 만드는 콘텐츠를 두지 않는다: 씬은 코드로 만들고, 그림은 처음에는 코드로 그린 도트다(나중에 아트로 바꾼다).

### 7.5 PC와 모바일

- 모든 기능은 마우스와 터치 둘 다로 쓴다. 턴제라 거의 모든 입력이 "누르기"다. 마우스 올리기에만 기대는 정보는 누르고 있기로도 보이게 한다
- UI는 휴대폰 가로(주 화면)·세로와 작은 PC 창(800×600)에 모두 들어가야 한다. 크기는 `Ui`의 점 단위로 잡고, 손가락으로 누를 단추는 44점 이상
- 처음 UI는 코드만으로 그리고 시험 도구가 눌러 볼 수 있는 IMGUI로 만든다(빠른 시제품). 글자는 화면의 실제 픽셀 크기로 그려 휴대폰에서도 또렷하다(`Client/Ui.cs`). 출시 전 다듬기 단계(M6)에서 UI Toolkit으로 옮길지 정한다
- 렌더 파이프라인은 시제품 동안 기본(Built-in)이다. 설정 에셋이 필요 없어 에디터 없이도 빌드가 된다. 2D 조명이 필요해지는 아트 단계(M6)에서 URP 2D로 옮길지 정한다

### 7.6 웹 데모와 자동 확인

푸시마다 GitHub Actions(GameCI)가 웹으로 빌드해 GitHub Pages에 올린다. 클라우드 세션은 배포가 끝나기를 기다려 헤드리스 Chromium으로 PC와 휴대폰 화면에서 실제 클릭·탭으로 플레이해 보고 사진을 확인한다(`Docs/Playtest.md`). 사람은 손맛, 소리, 실제 휴대폰 감각, 재미만 본다.

## 8. 작업 방식

- **클라우드 세션**: 코드, 데이터, 테스트, 문서. 웹 데모 배포 뒤 클라우드 플레이 시험
- **로컬 세션(Unity 에디터가 있는 컴퓨터)**: 에디터가 필요한 일(`.meta`, 씬, `ProjectSettings/`, 아트). `LOCAL_TASKS.md`
- **사람**: 계정·라이선스·저장소 설정, 직접 해 보는 느낌
- 자세한 규칙은 `CLAUDE.md`

## 10. 열린 질문

- 챕터 수와 한 챕터 길이(초안 5챕터, 45~70분)
- 서사 전체를 다른 이야기로 바꿀지(사용자: 바뀔 수 있다. 그래서 이야기는 데이터에만 둔다, `Narrative.md` 이야기 바꾸기)
- 영웅이 죽는 규칙: 지금 기본값은 "영영 죽지 않고, 쓰러질 때마다 상처(최대 생명력 −10%, 여관에서 낫는다)"(2026-11-10, `Combat.md` 상처). 영구 사망이나 성소에서 되살리기로 바꿀지는 사용자가 정한다
- 지도 크기와 생성 방식(손으로 만든 큰 틀 + 무작위 칸 내용을 초안으로 한다)
- 출시 가격 모델(유료 1회 구매 가정. 모바일 무료+해금은 나중에 정한다)
- 아트 방향: 도트(픽셀아트) 유지 또는 손그림 2D
- 사람이 둘일 때 셋째 영웅을 누가 맡는지(초안: 방장이 정한다)
